# Reference notes — expedia.com

Captured 2026-10-07 while building the embedded support chat and the two-surface
staff model. The automated browser audit of the reference is written to
`ux-audit-reference.md`; this file records the *structural* reference and what it
changed in this repository.

## Why this is a separate file

`docs/ux-audit-reference.md` is generated by `pnpm ux:audit:reference` and is
overwritten on every run. The observations below were gathered with a real
browser, so they belong somewhere durable.

Headless Chromium cannot render expedia.com from this container: the site
answers with an anti-bot interstitial. The content below was retrieved with an
anti-bot-capable fetcher, which returns the rendered DOM rather than the raw
HTML, so it reflects what a browser would see.

## Homepage structure

The homepage is a **vertical switcher over one search panel**:

| Region | Content |
| --- | --- |
| Hero | “The one place you go to go places” |
| Product tabs | Stays · Flights · Cars · Packages · Things to do · Cruises — each with a pictogram icon |
| Search panel | `Where to?` · `Dates` · `Travelers`, with a `Room 1 / Adults / Children` sub-panel for stays |
| Secondary CTA | “Add a flight to Bundle & Save\*” |
| Promotional rail | “Sale ends soon: Members save up to 30%” — with an explicit end date and a `Book now` action |

Two things are worth copying as a *pattern* rather than as code:

1. **One search box, switched by product.** The panel does not navigate away when
   the tab changes — the same real estate is re-purposed. EasyTrip already does
   this (`SearchExperience` with `typeIn`), and the audit confirmed the
   equivalent layout has no overflow defects at 390px.
2. **Every promotion carries an end date and a single action.** The banner is
   not a decorative strip; it states the deadline and links to the offer. This
   is why `PromoBanner` in this repo has `startsAt`/`endsAt` and a click
   counter rather than free-text alone.

## Help centre structure

`/help` is **article-first with a categorised index**, not chat-first:

| Region | Content |
| --- | --- |
| Greeting | “Hi, Traveler — How can we help?” |
| Primary control | A search box over help articles |
| Index | Category tiles: Flights, Refunds & Charges, Packages, Stays, Cars, Cruises, Things to do, Account, Privacy, Security, Travel Alerts, Loyalty & Rewards |
| Footer | App-install promo with a QR code |

### What this changed in EasyTrip

- **Categories mirror the product taxonomy.** Every tile is a product type or a
  money-flow topic (`Refunds & Charges`). `SupportConversation.subject` and the
  optional `orderId` link exist for the same reason: a support thread should
  arrive already labelled with what it is about, so an agent does not have to
  open it to find out. The inbox renders the subject and the related order in the
  list row.
- **A named greeting.** The reference opens with the traveller's name. The widget
  greeting does the same (`chat.greetingNamed`), read from the local session
  rather than by adding a request.
- **Scope difference, stated deliberately.** The reference is *article-first*
  with contact as an escalation. This repository implemented a **1:1 live chat**
  because that is what was asked for; a knowledge base is a separate, larger
  piece of work and deliberately out of scope. The chat is the escalation path,
  not a replacement for help articles.

## What was *not* carried over

- **No AI assistant.** The reference has an automated assistant; this
  implementation is a human queue. An automated responder that cannot actually
  resolve an issue is worse than none, and it would need a knowledge base first.
- **No anonymous threads.** The reference lets a signed-out visitor start a
  session. EasyTrip requires sign-in, because an anonymous thread needs an
  identity the API does not issue and is a spam surface. The widget still appears
  to guests and explains what sign-in unlocks.
- **No article search.** Out of scope; the search box on the reference is a
  help-article index, which this repository does not have.
